Named cross-references for Astro. Declare an anchor anywhere in your content,
link to it by name from anywhere else in the site. Links stay valid even when content
moves, because the name travels with the content.

<PkgMeta pkg="astro-better-refs" />

## Installation

```shell-session
npm install astro-better-refs
```

## Setup

<Steps>

### Register the integration

In `astro.config.ts`:

```ts
import astroRefs from 'astro-better-refs';

export default defineConfig({
  integrations: [
    astroRefs({
      collections: [
        { src: 'src/content/docs', base: '/docs' },
      ],
    }),
  ],
});
```

### Declare refs in your content

You can declare a ref in any of the following ways:

* **Frontmatter**
  ```yaml
  ---
  ref: my-page-name
  ---
  ```

* <Ref id="section-heading-suffix" />

  **Section heading suffix**

  ```md
  ## Jumbo Potatoes {potato-section}
  ```

  The `{potato-section}` suffix is stripped from the rendered heading.
  
* **`<Ref>` component**
  ```mdx escape
  import Ref from 'astro-better-refs/Ref.astro';
  <Ref id="my-anchor" />
  ```

### Link by name

Use the `ref:` URL scheme anywhere you write a link:

```md
[See the potato section](ref:potato-section)
[Jump to the heading suffix docs](ref:section-heading-suffix)
```

Refs work anywhere a Markdown link does.
The target doesn't have to be a heading; a `<Ref>` placed anywhere in the page works just as well.

</Steps>

## Integration options

| Option | Type | Description |
|--------|------|-------------|
| `collections` | `{src, base}[]` | Content directories to scan for ref declarations |

## Use with Sätteri

When `markdown.processor` is a Sätteri processor, the integration adds its Sätteri plugin to that processor instead of building a unified one. The same setup works unchanged.

To cover MDX as well, or to share one ref map across several processors, pass a `state` object to the integration and add the plugin yourself. The integration then only scans and reports:

```ts title="astro.config.ts"
import mdx from '@astrojs/mdx';
import { satteri } from '@astrojs/markdown-satteri';
import astroRefs from 'astro-better-refs';
import { refs } from 'astro-better-refs/satteri';

const state = { refMap: null, brokenRefs: [], duplicates: [] };
const processor = satteri({ mdastPlugins: [refs({ state })] });

export default defineConfig({
  markdown: { processor },
  integrations: [
    mdx({ processor }),
    astroRefs({ collections: [{ src: 'src/content/docs', base: '/docs' }], state }),
  ],
});
```

With unified, the same pattern uses `remarkAstroRef` from `astro-better-refs`.

## `Ref` component props

| Prop | Type | Description |
|------|------|-------------|
| `id` | `string` | The ref name to declare at this location |

<Admonition type="tip" title="Multiple aliases">
  A page can declare multiple ref names in frontmatter:
  ```yaml
  ---
  refs:
    - my-page-name
    - legacy-name
  ---
  ```
</Admonition>
